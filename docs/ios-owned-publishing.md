# iOS owned publishing — ordinary pilot

US-MONOGRAPH-PUBLISHING-01, November 21, 2026. Source implementation for the existing iOS Notesnook fork. Native acceptance and device release are recorded separately below.

The new iOS Publish sheet uses the existing Heal Earth account in Keychain. It does not change the global Notesnook API host, send a sync token to Heal Earth, or fall back to publishing upstream when Heal Earth is unavailable. The first release publishes an unrestricted, revocable saved snapshot. Listing is a separate, unchecked choice. Archive retention, new password/key modes and one-read creation are not enabled in this first-party UI; older Notesnook shares remain accessible through an explicitly separate manager.

Transport stays inside google-session.ts: fixed first-party path allowlist, cookies omitted, redirects rejected, bounded response size/timeout, expected account header and fresh Keychain/selected-account checks before and after network work. UI and the editor never receive the bearer. Local publication state lives in per-account/per-source-note Keychain records, separate from legacy Monograph records and original notes. A timeout preserves the same source identity for retry; HTTP 202 retains unpublish_pending and offers Retry removal. Late responses after account changes cannot overwrite the newly selected account.

The client looks up and exports the saved local content with its available media, rejects locked/deleted/oversized sources, and re-reads modification identities after preparation. It submits expectedRevision from freshly fetched owner metadata; the server checks that precondition while holding its publication lease. A stale ordinary draft cannot overwrite newer restricted access. Protected existing owned editions can be withdrawn, but this initial sheet cannot weaken their controls. The link selector requires readiness and both rollout gates for canonical URLs; otherwise it uses the validated isolated reader URL. No key-bearing URL, password, note body or credential is written to diagnostics.

Publishing from an actively open editor is deliberately blocked in this first release: save and return to Notes, then use the note's Publish action. The existing editor lacks a confirmed flush/acknowledgement API; this implementation does not pretend a timer proves unsaved text is persisted. End-to-end unsaved-editor publication remains a separate improvement. Existing native private note databases, media originals, encryption keys and login items are not migrated or reset.

Validation: mobile TypeScript passed; all 92 mobile script tests passed, including 11 new publishing cases for account separation, late responses, first-party bearer confinement, failure/status propagation, 202 cleanup, readiness/link validation, size/locked flow and idempotent source retries. Targeted lint has zero errors; existing warnings remain in older touched files. Backend adds access metadata and optional revision preconditions; all 201 backend tests pass. This does not establish installed-client acceptance by itself.

Backend controlled pilot was deployed and its browser/signed-out lifecycle verified. See heal-earth-club/docs/monograph-publishing-verification.md and docs/evidence/publishing. Archive retention and native branded links remain false; the owner allowlist is the only enabled publisher account.

Review follow-up: absent/non-boolean access metadata is treated as restricted, so a mixed-version response cannot authorize an ordinary downgrade. Cached publication controls load before independent capability/metadata refreshes, preserving withdrawal access when capability lookup fails. Canonical link selection additionally checks the capability account, contract version and publishing gate. Saved account restoration runs on sheet entry before offering sign-in. Regression tests cover these guards.

## Installed native verification — November 21

A Release simulator build used normal Google sign-in with the authorized owner, published a harmless saved note unlisted, opened its signed-out reader, explicitly enabled profile listing, and updated the publication title while retaining its alias/edition ID. Primary and independent recovery snapshot bytes matched. The original private note title and body remained unchanged.

After installing the final build over the existing app and restarting, the saved account, updated publication title and listing preference restored without another sign-in. Native Unpublish completed; anonymous canonical, reader and snapshot routes all returned 404, the listing disappeared, D1 was unpublished/disabled with no blob key, and both revisions were absent from both primary and recovery buckets. No app database was reset. Evidence: docs/evidence/publishing/ios-live-lifecycle-2026-11-21.json and ios-reader-2026-11-21.png. Local restart/withdrawal screenshots were retained outside the staged handoff because they show the account email.

The final signed physical archive passed codesign verification and was installed and launched on the connected iPhone without data reset: org.healearth.ohai, version 1.0.0 build 1. Physical user acceptance is pending and is distinct from the completed real simulator/live-server lifecycle. Archive and native branded flags remain off. General availability, protected native creation and full account-deletion/archive controls are not claimed.
